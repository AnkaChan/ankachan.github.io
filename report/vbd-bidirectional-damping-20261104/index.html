VBD contact damping: one-sided vs bidirectional

Seven Franka and Allegro cloth manipulation cases from the collision benchmark, each run twice with the same source, settings, seeds and hand commands. The only difference is the new SolverVBD option contact_damping_bidirectional: False (one-sided: damping only while a contact gap closes; the constructor default when these runs were made) versus True (bidirectional: damping also while the gap opens, with the matching Hessian; the constructor default on the branch since the afternoon of 2026-11-04).

Standard VBD elasticity, fast math off, rigid-soft DAT on, merged OGC edge rule, contact stiffness capped at 10x the membrane coefficient, 30 Hz frames, ten substeps (dt = 1/300 s), 60 s hold. Contact damping coefficient kd = 0.1 in every scene. Single runs; they do not establish repeatability.

Update, 2026-11-04 afternoon

Anka decided to make the bidirectional damping the default. The branch now carries the option (b989e846c), the default change (36590004e) and the rebase onto upstream main 7f0c13af6. Two more commits followed: the tuning-guide additions (81fd7250a) and an objective gap rate for the self-contact and rigid-rigid dampers (68c18328a), which the repo's rigid-motion test required once the two-sided gate became the default. The arm labels on this page were changed to match: One-sided (closing only; previous default) is the run with contact_damping_bidirectional=False, Bidirectional (new default) the run with True. The runs themselves were made at commit c49851e53, before these follow-up commits, and are unchanged. The poker-card results below were added in the same update. Later still, on Anka's suggestion, the option was split by contact type (commit 2cd7d288f): soft_contact_damping_bidirectional (default True; self-contact and rigid-soft) and rigid_contact_damping_bidirectional (default False; rigid-rigid). The runs on this page used the earlier single flag, which set all three laws at once.
